# Задача: claude-remote — удалённый веб-терминал для Claude Code на моём Windows-ноуте

Ты работаешь в пустой папке `claude-remote`. Нужно с нуля написать на Go небольшой сервер, который позволяет мне с телефона (через браузер) работать в терминале на моём личном Windows 11 ноуте, где запущен Claude Code, и смотреть скриншоты экрана ноута.

Перед началом: инициализируй git-репозиторий (`git init`), создай ветку работы, но НЕ делай коммитов и пушей, пока я не попрошу. Не добавляй атрибуцию и трейлеры в коммиты, когда дойдёт до них.

## Контекст и цель

- Ноут остаётся включённым дома, я ухожу. С телефона открываю страницу, вижу живой терминал, в котором работает `claude`, пишу в него, одобряю разрешения, прерываю (Ctrl+C), и могу нажать кнопку «Экран» и получить скриншот экрана ноута.
- Доступ только через Tailscale (приватная сеть WireGuard). Порт НЕ должен быть доступен из интернета и из обычной локальной сети.
- Ноут личный, пользователь один. Это не многопользовательский сервис.
- Безопасность критична: эта штука даёт полный шелл на ноуте. Любая дыра = полный захват машины.

## Архитектура

```
Телефон (браузер, xterm.js) ──Tailscale──► сервер на ноуте
   WebSocket: ввод/вывод/resize   ◄──►  ConPTY  ◄──►  claude (или powershell)
   HTTP GET /screenshot           ◄──     захват экрана → PNG
```

## Технические требования

**Язык и зависимости**
- Go (последняя стабильная версия, указать в go.mod). Минимум зависимостей.
- ConPTY: `github.com/UserExistsError/conpty`. Если окажется непригодной, предложи альтернативу и объясни, но не выбирай молча.
- WebSocket: `github.com/coder/websocket` (или gorilla/websocket, выбери и обоснуй одной строкой).
- Скриншот: `github.com/kbinani/screenshot` или прямой вызов GDI/DXGI. Выбери проще, обоснуй.
- Веб-клиент: xterm.js и addon-fit. Раздавай статику из бинарника через `embed`, без внешних CDN и без npm-сборки (положи готовые минифицированные файлы xterm в `web/vendor/`, зафиксируй версии, проверь, что скачал их с официального источника, и запиши версии и sha256 в `web/vendor/VERSIONS.md`).
- Сборка одним бинарником: `go build -o claude-remote.exe ./cmd/claude-remote`.
- Код должен собираться на Windows. Если захочешь разнести OS-специфичный код, используй пары `*_windows.go` / `*_other.go`, чтобы `go vet ./...` проходил и на Linux (для CI).

**Структура**
```
cmd/claude-remote/main.go     — флаги, конфиг, запуск
internal/server/              — HTTP, WebSocket, маршруты, middleware
internal/auth/                — токен, rate limit, сравнение в постоянное время
internal/session/             — постоянная PTY-сессия, ring buffer, подписчики
internal/screen/              — захват экрана
internal/config/              — загрузка конфига, генерация токена
web/                          — index.html, app.js, style.css, vendor/
README.md                     — установка, настройка Tailscale, использование, угрозы
```

## Поведение сервера

1. **Привязка**: сервер слушает ТОЛЬКО на адресе Tailscale-интерфейса ноута (`100.64.0.0/10`). Адрес определи автоматически, перебрав сетевые интерфейсы; можно переопределить флагом `--listen`. Если Tailscale-адрес не найден, сервер НЕ должен молча слушать на `0.0.0.0`: он падает с понятной ошибкой. Явный `--listen 127.0.0.1:PORT` разрешён (для тестов). Значение `0.0.0.0` и `::` отклоняй с ошибкой, если нет отдельного флага `--i-know-this-is-dangerous`. Порт по умолчанию 8443 (или выбери другой и задокументируй).
2. **TLS**: Tailscale уже шифрует трафик, но браузеры на телефоне капризны к `http://` для PWA и буфера обмена. Реализуй два режима: (а) по умолчанию HTTP поверх Tailscale с пометкой в README про последствия; (б) опционально HTTPS-сертификат через `tailscale cert` (флаги `--tls-cert`, `--tls-key`). Не изобретай собственный CA.
3. **Постоянная сессия**: один процесс (по умолчанию `claude` в рабочей папке из `--workdir`, команда переопределяется флагом `--cmd`) в ConPTY. Он запускается при старте сервера (или лениво при первом подключении, выбери и обоснуй) и живёт независимо от того, подключён ли клиент. Если процесс завершился, перезапускай по явной команде с клиента (кнопка «Перезапустить»), а не в бесконечном цикле.
4. **Ring buffer**: храни последние ~256 КБ вывода. Новый клиент сразу получает этот буфер, чтобы увидеть текущий экран. Учти, что буфер может резаться посреди escape-последовательности: при отправке клиенту обеспечь, чтобы терминал не ломался (например, начинай с сброса состояния и отрезай до ближайшего безопасного места, либо ограничь буфер границами строк). Опиши выбранное решение в комментарии.
5. **Подключения**: допускай несколько одновременных WebSocket-клиентов (телефон + браузер на ноуте). Ввод принимается от всех, вывод рассылается всем. Медленный клиент не должен блокировать остальных (буферизованный канал, отключение при переполнении).
6. **Resize**: клиент присылает размеры (cols, rows), сервер вызывает resize ConPTY. При нескольких клиентах используй размер последнего активного.
7. **Протокол WebSocket**: бинарные кадры для данных терминала, текстовые JSON-кадры для управления (`{"type":"resize","cols":..,"rows":..}`, `{"type":"restart"}`). Ограничь максимальный размер входящего кадра.
8. **Скриншот**: `GET /screenshot` возвращает PNG основного дисплея (параметр `?display=N` для выбора, `?scale=0.5` для уменьшения, чтобы мобильный трафик был небольшим; по умолчанию уменьшай до ширины ~1280). Скриншот требует авторизации так же, как и всё остальное. Заголовок `Cache-Control: no-store`. Захват делай в отдельной горутине с таймаутом, чтобы зависший захват не вешал сервер.
9. **Корректное завершение**: по Ctrl+C/сигналу закрой WebSocket-ы, убей дочерний процесс и всё дерево (на Windows это важно: используй Job Object, чтобы дочерние процессы Claude Code не оставались сиротами).

## Безопасность (обязательно, это главная часть)

- **Токен**: при первом запуске сгенерируй криптостойкий токен (минимум 32 байта, `crypto/rand`, base64url) и сохрани в `%APPDATA%\claude-remote\config.json` с правами только для текущего пользователя (ACL на Windows: убери наследование, оставь только владельца; проверь это). Токен печатай в консоль только один раз при генерации. Показывай его в виде, удобном для копирования, но не пиши в логи при последующих запусках. Команда `claude-remote token rotate` генерирует новый.
- **Аутентификация**: каждый HTTP-запрос и WebSocket-апгрейд требует токен. Принимай токен через cookie `HttpOnly; SameSite=Strict` (устанавливается после логина на странице входа через POST) или заголовок `Authorization: Bearer`. НЕ принимай токен в query-строке (попадает в историю и логи). Сравнение токена только `subtle.ConstantTimeCompare`.
- **Rate limit**: не более 5 неудачных попыток на IP за 5 минут, дальше блокировка на экспоненциально растущее время; учитывай, что за Tailscale IP клиента стабилен. Лимит хранится в памяти.
- **Origin check**: для WebSocket проверяй заголовок `Origin` против ожидаемого хоста (защита от cross-site WebSocket hijacking). Без Origin или с чужим Origin отклоняй.
- **CSRF**: все изменяющие запросы (POST) проверяют Origin/Host и требуют cookie с SameSite=Strict.
- **Заголовки**: `Content-Security-Policy` (default-src 'self', без inline-скриптов; разреши ws: на тот же хост), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.
- **Таймауты**: ReadHeaderTimeout, IdleTimeout на HTTP-сервере; пинг/понг WebSocket каждые 30 секунд, закрывай мёртвые соединения.
- **Логи**: логируй подключения, отказы аутентификации и скриншоты (время, IP, результат). НИКОГДА не логируй токен, содержимое ввода/вывода терминала и cookie. Добавь тест, который это проверяет.
- **Рабочая папка и команда**: `--cmd` и `--workdir` задаются только флагами запуска, никогда не приходят от клиента. Клиент не может выбрать, что запускать.
- **Нет файловых операций с клиента**: никаких загрузок/скачиваний файлов, никаких произвольных путей в эндпоинтах.
- **Зависимости**: после добавления выполни `go mod tidy`, `go mod verify`, и запусти `govulncheck ./...` (если не установлен, скажи мне, не пропускай молча).

## Веб-клиент

- Одна страница, адаптивная под телефон, тёмная тема.
- Экран входа (поле токена, POST на `/login`, cookie ставит сервер). Токен не хранится в localStorage.
- Терминал на весь экран (xterm.js + addon-fit), автоподгонка при повороте экрана и появлении клавиатуры (используй `visualViewport`).
- Нижняя панель кнопок для клавиш, которых нет на мобильной клавиатуре: Esc, Tab, Ctrl+C, Ctrl+D, стрелки, Enter, `|`, `/`, `~`. Режим Ctrl как «залипающий» переключатель для комбинаций.
- Кнопка «Экран»: открывает оверлей со скриншотом (`/screenshot?scale=...`), с кнопкой «Обновить» и переключателем автообновления (раз в 5 секунд, выключен по умолчанию). Закрывается тапом.
- Кнопка «Перезапустить» (с подтверждением).
- Индикатор состояния соединения; автопереподключение с экспоненциальной задержкой. При переподключении очищай терминал и принимай свежий буфер.
- PWA: `manifest.webmanifest` и иконки, чтобы добавить на домашний экран. Service worker не нужен (не кэшируй ничего чувствительного).
- Никаких внешних ресурсов (шрифты, CDN, аналитика).

## Тесты

Тесты рядом с кодом (`*_test.go`). Обязательно покрой:
- `auth`: правильный/неправильный токен, rate limit и блокировка, отказ токена в query.
- `server`: WebSocket без аутентификации отклоняется; с чужим Origin отклоняется; `/screenshot` без аутентификации = 401; заголовки безопасности присутствуют; кадр больше лимита обрывает соединение.
- `session`: ring buffer (переполнение, порядок), рассылка нескольким подписчикам, медленный подписчик не блокирует остальных. Используй фейковый PTY (интерфейс), чтобы тесты не зависели от ConPTY.
- `config`: токен генерируется один раз, права на файл ограничены (тест может быть только под Windows через build tag).
- `listen`: отказ на `0.0.0.0` и `::` без опасного флага.
- Лог не содержит токена (тест перехватывает вывод логгера).

Интеграционный тест на реальном ConPTY сделай под build tag `windows`, запускающий `cmd /c echo hello` и проверяющий вывод.
