# agent-remote

Удалённый веб-терминал для AI-агентов на личном Windows 11 ноутбуке. С телефона (через браузер) вы видите живой терминал Claude Code или OpenAI Codex CLI, пишете в него, одобряете запросы, прерываете (Ctrl+C) и по кнопке «Экран» получаете скриншот экрана ноутбука.

> Сейчас имя исполняемого файла и каталога конфигурации остаётся `claude-remote` для совместимости с уже установленными экземплярами. Название проекта и интерфейса — **agent-remote**.

Один Go-бинарник, без базы данных и без пользователей: токен один, пользователь один.

> **Внимание.** Эта программа даёт полный шелл на вашем ноутбуке. Любая дыра означает полный захват машины. Читайте раздел «Модель угроз».

```
Телефон (браузер, xterm.js) ──Tailscale──► сервер на ноуте
   WebSocket: ввод/вывод/resize   ◄──►  ConPTY  ◄──►  Claude Code, Codex или powershell
   HTTP GET /screenshot           ◄──     захват экрана → PNG
```

## Установка Tailscale

1. Установите Tailscale на ноутбук и на телефон: <https://tailscale.com/download>.
2. Войдите в **один и тот же** аккаунт на обоих устройствах.
3. **Включите 2FA** у провайдера входа (Google, Microsoft, GitHub и т. д.). Кто получит доступ к вашему аккаунту Tailscale, тот окажется в вашей сети.
4. Убедитесь, что у ноутбука есть адрес вида `100.x.y.z` (`tailscale ip -4`).
5. Включите на ноутбуке автозапуск Tailscale (по умолчанию включён).
6. По желанию в консоли администратора Tailscale включите *Device approval* и настройте ACL так, чтобы к ноутбуку по порту 8443 могли обращаться только ваши устройства.

## Отключение сна ноутбука

Пока ноутбук спит, сервер недоступен:

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

Для работы от батареи используйте `-dc` вместо `-ac`. Крышку лучше не закрывать (или задайте в настройках питания «Ничего не делать» при закрытии крышки).

## Сборка

Нужен Go (версия указана в `go.mod`).

```powershell
go build -o claude-remote.exe ./cmd/claude-remote
```

## Первый запуск и токен

```powershell
.\claude-remote.exe --workdir C:\Users\you\projects\my-project
```

- Сервер сам находит адрес Tailscale (`100.64.0.0/10`) на сетевом интерфейсе с именем `Tailscale` и слушает только на нём, порт **8443** (диапазон 100.64/10 используют и мобильные операторы, поэтому одного адреса недостаточно). Если Tailscale не найден, сервер завершается с ошибкой и **не** слушает `0.0.0.0`.
- При первом запуске в консоли **один раз** печатается токен. Скопируйте его в менеджер паролей. Токен хранится в `%APPDATA%\claude-remote\config.json` (доступ только вашему пользователю) и больше нигде не показывается и не пишется в логи.
- Новый токен (например, после утечки): `.\claude-remote.exe token rotate`, затем перезапустите сервер. После перезапуска все старые сессии браузера перестанут работать.

### Флаги

| Флаг | Назначение |
|---|---|
| `--project ИМЯ=ПУТЬ` | разрешённый проект; флаг можно повторять. Клиент выбирает проект только по имени |
| `--workdir DIR` | короткая запись одного проекта (имя берётся из папки) |
| `--lock-timeout 5m` | через сколько без действий блокировать приложение, если задан PIN (`0` = только при каждом открытии) |
| `--codex-cmd`, `--no-codex`, `--no-codex-notify` | настройка Codex CLI (см. раздел «Claude Code или Codex») |
| `--no-power`, `--keep-awake`, `--no-alerts` | питание ноутбука (см. раздел «Состояние ноутбука и управление питанием») |
| `--record` | записывать весь вывод терминала в файлы (**содержит секреты**, по умолчанию выключено) |
| `--cmd CMD` | что запускать (по умолчанию `claude`; можно `powershell`) |
| `--listen IP:PORT` | переопределить адрес. `127.0.0.1:PORT` разрешён для тестов; `0.0.0.0` и `::` отклоняются |
| `--i-know-this-is-dangerous` | разрешить `0.0.0.0` / `::`. **Не используйте** |
| `--tls-cert`, `--tls-key` | включить HTTPS (см. ниже) |
| `--allow-host NAME` | дополнительное имя в заголовке `Host` (например, имя MagicDNS), если заходите не по IP |
| `--config-dir DIR` | другая папка конфига (для тестов) |

`--cmd`, `--project` и `--workdir` задаются только при запуске; клиент не может выбрать, что и где запускать, а только выбрать проект из вашего списка по имени.

Процесс сессии запускается, когда вы создаёте сессию, и дальше живёт независимо от того, подключён ли кто-то. После завершения процесса он **не** перезапускается сам: нажмите «Перезапустить».

### HTTP и HTTPS

По умолчанию используется обычный **HTTP поверх Tailscale**. Трафик уже шифруется WireGuard между вашими устройствами, но браузер считает страницу небезопасной: на телефоне могут не работать буфер обмена и часть PWA-функций, а cookie не получает флаг `Secure`.

Для HTTPS используйте сертификат Tailscale (включите HTTPS и MagicDNS в консоли администратора):

```powershell
tailscale cert my-laptop.tailnet-name.ts.net
.\claude-remote.exe --tls-cert my-laptop.tailnet-name.ts.net.crt --tls-key my-laptop.tailnet-name.ts.net.key --allow-host my-laptop.tailnet-name.ts.net
```

Затем заходите на `https://my-laptop.tailnet-name.ts.net:8443`. Собственный CA не используется.

## Проверка настройки и автозапуск одной командой

```powershell
.\claude-remote.exe doctor --project мой-проект=C:\Users\you\projects\my-project
.\claude-remote.exe install --project мой-проект=C:\Users\you\projects\my-project
```

`doctor` проверяет Tailscale, наличие `claude`, папки проектов, права на токен, HTTPS и автозапуск и подсказывает, как исправить каждую проблему. `install` создаёт задачу Task Scheduler на вход пользователя (через XML, поэтому длинные списки `--project` не упираются в лимит `schtasks /TR`); все флаги после `install` передаются серверу как есть. Убрать: `.\claude-remote.exe uninstall`.

## Автозапуск вручную (Task Scheduler)

Запуск при входе пользователя, с задержкой 30 секунд, чтобы поднялся Tailscale. Подставьте свои пути; `/IT` нужен, чтобы процесс работал в вашей интерактивной сессии (иначе скриншоты не получатся):

```powershell
schtasks /Create /TN "claude-remote" /SC ONLOGON /DELAY 0000:30 /RU "$env:USERNAME" /IT /RL LIMITED /F `
  /TR "\"C:\tools\claude-remote\claude-remote.exe\" --workdir \"C:\Users\you\projects\my-project\""
```

Удалить: `schtasks /Delete /TN "claude-remote" /F`. Остановить сейчас: `schtasks /End /TN "claude-remote"`.

Если Tailscale не успел подняться, сервер завершится с ошибкой; запустите задачу вручную (`schtasks /Run /TN "claude-remote"`) или увеличьте задержку.

## Использование с телефона

1. Откройте `http://100.x.y.z:8443` (или HTTPS-имя). Введите токен: сервер поставит cookie `HttpOnly; SameSite=Strict` со случайным идентификатором сессии (сам токен в cookie не кладётся). Токен нигде не сохраняется в браузере.
2. Работайте в терминале. Нижняя панель: Esc, Tab, Ctrl (залипающая: нажмите Ctrl, затем букву), ^C, ^D, стрелки, Enter, `|`, `/`, `~`.
3. **Экран**: открывает скриншот (по умолчанию уменьшен до ширины ~1280). «Обновить», «авто (5 с)». Тап по картинке закрывает.
4. **Перезапустить**: завершает процесс вместе со всеми дочерними и запускает заново (с подтверждением).
5. Индикатор показывает состояние соединения; при обрыве клиент переподключается с нарастающей задержкой. При переподключении терминал очищается и приходит свежий буфер (последние ~256 КБ вывода).
6. Добавьте страницу на домашний экран (PWA).

Одновременно можно подключить несколько клиентов (телефон и браузер на ноутбуке). Ввод принимается от всех, вывод получают все, размер терминала берётся от последнего приславшего resize.

## Проекты и сессии

Можно держать до 8 сессий одновременно (разные проекты, несколько разговоров в одном проекте). В шапке страницы кнопка с названием сессии открывает список:

- тап по сессии открывает её; ✕ закрывает и останавливает процесс;
- **＋ Новая сессия**: выбираете проект (если проект один, шаг пропускается), затем **«Новая сессия»** или **«Продолжить прежнюю»**: сервер читает список ваших разговоров из `~/.claude/projects` и запускает `claude --resume <id>`, как в терминале.

Сессии живут, пока работает сервер. Заголовки берутся из первого вашего сообщения в разговоре. Это внутренний формат Claude Code: если он изменится, список может стать неполным (сам запуск не пострадает).

## Claude Code или Codex

В начале новой сессии спрашивается, **чем пользоваться**: Claude Code или OpenAI Codex CLI (если на ноутбуке найден только один, вопрос пропускается). Дальше всё так же: проект, затем новая сессия или продолжение прежней (`claude --resume <id>` / `codex resume <id>`). В списке сессий у каждой указан инструмент.

Что работает для Codex:
- запуск и продолжение разговоров, выбор из истории проекта и **из всех папок** (вкладки «Claude Code / Codex» в «Прошлых разговорах»); история читается из `~/.codex/sessions` (в том числе сжатые `.zst`), для названий используется `session_index.jsonl`;
- уведомление «Codex закончил» через `notify` Codex (нужен HTTPS, как для Claude);
- пульс по активности вывода («работает / ждёт»);
- голос, загрузка файлов, чтение вывода, PIN, скриншоты работают одинаково.

Чего для Codex нет:
- **уведомления «ждёт разрешения»** и точного состояния «работает»: у Codex нет таких хуков, пульс только угадывается по выводу;
- **списка сессий, открытых в окнах на ноутбуке**, и их закрытия (`claude agents` есть только у Claude Code). Если разговор Codex открыт в окне, закройте окно сами, прежде чем продолжать его с телефона.

Важно про `notify`: сервер запускает Codex с параметром `-c notify=[…]`. Он **заменяет** `notify` из `~/.codex/config.toml` только для терминалов, запущенных через сервер (сам файл не меняется). Если у вас там настроена своя программа (например, для десктопного приложения), она в этих терминалах вызываться не будет. Чтобы этого избежать, запускайте сервер с `--no-codex-notify`, но тогда не будет и уведомления «закончил».

Флаги: `--codex-cmd КОМАНДА` (по умолчанию `codex`), `--no-codex` (не предлагать Codex), `--no-codex-notify`.
## Сессии Claude, открытые на ноутбуке

В списке сессий внизу раздел **«На ноутбуке»**: все сессии `claude`, которые сейчас открыты где угодно на ноутбуке (в других папках и окнах), с именем, папкой и состоянием («работает» или «ждёт»). Список берётся из `claude agents --json`. Пути и номера процессов на телефон не отправляются.

- **Сессия в окне терминала.** Подключиться к чужому окну Windows не даёт, поэтому делается так: вы подтверждаете предупреждение, сервер **закрывает процесс этого окна** на ноутбуке и продолжает тот же разговор у вас (`claude --resume`). Так не получится двух копий, пишущих в один разговор. Всё несохранённое в окне может потеряться; для сессии, которая **работает прямо сейчас**, нужно отдельное, второе подтверждение (задача будет прервана). Само окно терминала на ноутбуке останется открытым, но `claude` в нём завершится.
- **Фоновая сессия** (`claude --bg`): сервер подключается к ней через `claude attach`, ничего не закрывая. Если хотите, чтобы сессии, которые вы запускаете на ноутбуке, можно было подхватывать вживую, запускайте их как `claude --bg`.

Как это защищено: клиент присылает только идентификатор сессии Claude; папку, процесс и имя сервер каждый раз берёт заново из `claude agents`. Перед закрытием проверяется, что процесс всё ещё тот самый (имя исполняемого файла `claude`/`node` и время запуска совпадают с отчётом `claude agents`: номера процессов в Windows переиспользуются). Свои терминалы сервера никогда не закрываются. Если закрыть процесс не удалось, разговор **не** продолжается (иначе получились бы две копии).

Важно: это единственное место, где сессия может работать в папке вне вашего списка `--project`: папка берётся из самого `claude`, а не от клиента.

## Прошлые (закрытые) разговоры из любых папок

В списке сессий кнопка **«Прошлые разговоры из всех папок…»**: все разговоры `claude` с ноутбука, не только открытые сейчас, новые сверху, с **поиском** по названию и папке. Выбор продолжает разговор (`claude --resume`) в той папке, где он был начат: папку сервер берёт из файла самого Claude, а клиент присылает только идентификатор разговора.

Если выбранный разговор сейчас открыт в окне на ноутбуке, сервер откажет и подскажет найти его в разделе «Открыты на ноутбуке» (там окно можно закрыть и продолжить здесь): иначе два процесса писали бы в один разговор.
## Состояние ноутбука и управление питанием

В шапке рядом с кнопкой «Экран» значок **батареи** (процент, молния при подключённом питании; жёлтый при 20% и ниже, красный при 10% и ниже). Нажатие, или меню ⋯ → **«Состояние ноутбука»**, открывает экран «Ноутбук»:

- **батарея**: процент, от сети или от батареи, сколько осталось работать;
- **температура**: самая горячая системная зона (ACPI); отдельно отмечается, если процессор снижает частоту. Windows без драйверов не показывает температуру самого процессора, так что это не CPU-датчик;
- **процессор, память, диски** (служебные разделы меньше 20 ГБ скрыты), **время работы**;
- **состояние экрана**: включён, притушен, **выключен**, **заблокирован**, **крышка закрыта**, сколько времени нет ввода, и «ноутбук спал с … по …», если он уходил в сон сам. Если экран не просто включён, в шапке появляется жёлтая плашка («Экран выключен», «Заблокирован», «Крышка закрыта»), а кнопка «Экран» желтеет; вместо чёрного скриншота показывается причина. Состояние берётся из событий Windows (дисплей, блокировка сессии, крышка, сон и пробуждение) и обновляется каждые 10 секунд. Пока ноутбук реально спит, сервер не работает вообще, поэтому телефон покажет обрыв связи, а после пробуждения объяснит, что был сон.

Обновляется каждые 5 секунд, пока экран открыт.

**Управление:**
- **Заблокировать экран**: сразу, с подтверждением.
- **Не давать ноутбуку засыпать**: переключатель; пока включён, Windows не уходит в сон сам, пока работает сервер (то же при запуске с `--keep-awake`). Экран может гаснуть и блокироваться.
- **Сон, гибернация, перезагрузка, выключение**: в два шага. Сначала сервер выдаёт одноразовый код (действует 30 секунд, привязан к вашему входу и к выбранному действию), затем действие выполняется только с этим кодом, а если задан PIN, то и с PIN (его запрашивают снова, а не полагаются на то, что приложение разблокировано минуту назад; PIN нужен и запросам с токеном, поэтому один украденный токен выключить ноутбук не может; неверные PIN считаются в тот же счётчик попыток).
  - **Перезагрузка и выключение** идут с отсрочкой 30 секунд, которую можно **отменить** с этого же экрана. Есть галочка «закрыть программы принудительно».
  - **Сон и гибернацию отменить нельзя**, и **разбудить ноутбук с телефона нельзя**: после сна Tailscale отключается, включать придётся вручную (крышка или кнопка). Об этом предупреждает подтверждение.

**Предупреждения на телефон** (нужен HTTPS и включённые уведомления): заряд 20% и 10%, пропало питание от сети, перегрев или троттлинг (85 °C и выше), мало места на диске (меньше 5 ГБ). Каждое срабатывает один раз и не повторяется, пока условие не пройдёт. Отключить: `--no-alerts`.

Флаги: `--no-power` убирает сон, гибернацию, перезагрузку и выключение (мониторинг, блокировка экрана и «не засыпать» остаются), `--keep-awake`, `--no-alerts`. `claude-remote doctor` предупредит, если эти действия доступны без PIN. **Рекомендуется** включить PIN (`claude-remote pin set`): тогда любое выключение требует его.
## PIN-блокировка

Cookie входа остаётся на телефоне 14 дней. Чтобы тот, у кого в руках разблокированный телефон, не получил доступ, можно включить PIN:

```powershell
.\claude-remote.exe pin set      # PIN 6–12 цифр, вводится на ноутбуке без отображения
.\claude-remote.exe pin remove   # убрать PIN
```

PIN задаётся и меняется **только на ноутбуке**: если бы это можно было делать с телефона, PIN подменили бы с него же. Сервер перезапускать не нужно.

Как работает:
- После входа токеном приложение просит PIN. Ключ разблокировки хранится только в памяти страницы, поэтому **каждое открытие приложения снова просит PIN**; возврат в приложение после паузы дольше 30 секунд тоже.
- Сервер сам блокирует приложение после `--lock-timeout` (по умолчанию 5 минут) без ввода: связь с терминалом разрывается, пока не введёте PIN. Вручную: меню **⋯ → Заблокировать сейчас**.
- PIN хранится в `lock.json` как хэш argon2id (доступ только вам). Неверный PIN: 5 ошибок с одного адреса дают блокировку с нарастанием (1, 2, 4 … минут), а 10 ошибок в одном входе завершают этот вход, и нужно заново вводить токен.
- Простые PIN (`000000`, `123456`) не принимаются.

Что PIN **не** защищает: запросы с заголовком `Authorization: Bearer <токен>` (скрипты и инструменты) идут мимо PIN, потому что тот, у кого есть токен, и так имеет полный доступ. PIN защищает работу в браузере с cookie, а не сам токен.

## Пульс сессии

Рядом с названием сессии: цветная точка и подпись.
- **работает** (синяя, пульсирует) со временем: Claude обрабатывает запрос;
- **ждёт вас** (янтарная, быстро мигает): нужно разрешение или ответ;
- **готово, N назад** (зелёная): Claude закончил;
- **завершена** (красная).

Состояние приходит от хуков `UserPromptSubmit`, `Notification` и `Stop`; для сессий без хуков (например, фоновых) «работает» определяется по недавнему выводу. То же показывается в списке сессий.

## Чтение вывода

- Меню ⋯ → **Читать вывод как текст** (или кнопка «Текст» в нижнем ряду): вся история терминала обычным выделяемым текстом с переносом строк; **поиск** (↑ ↓ между совпадениями), **копировать всё** или **последние 100 строк**.
- **Размер шрифта**: A− / A+ в этом окне и в меню; сохраняется на телефоне.

## Голосовой ввод

Кнопка 🎤 в нижнем ряду открывает поле: нажмите микрофон, говорите, текст появится в поле (можно поправить), затем **«Отправить ⏎»** (с Enter) или **«Вставить»** (без Enter). Ничего не отправляется автоматически. Язык: RU или EN.

Важно: речь распознаёт **браузер** (Chrome на Android), аудио обрабатывает сервис Google, нужен интернет и HTTPS. Это внешний сервис; не диктуйте секреты. Если браузер не умеет распознавать речь, используйте микрофон на клавиатуре телефона.

## Уведомления на телефон

Когда `claude` ждёт разрешения или закончил ответ, на телефон приходит push. Сервер запускает `claude` с `--settings`, где подключены хуки `Notification` и `Stop` (это официальный механизм Claude Code, никакого разбора текста терминала). Хук вызывает `claude-remote notify`, а тот передаёт событие серверу через локальный порт `127.0.0.1` (секрет генерируется при каждом запуске). Ваши собственные хуки в `~/.claude/settings.json` продолжают работать.

Что нужно:

1. **HTTPS.** Браузеры разрешают service worker и push только в защищённом контексте: настройте `tailscale cert` (раздел выше) и заходите по `https://имя.tailnet.ts.net:8443`.
2. В странице: меню **⋯ → Уведомления** и разрешение в браузере.
3. Ноутбуку нужен выход в интернет: сообщение уходит через push-сервис браузера (Google FCM, Mozilla, Apple, Windows). Содержимое шифруется ключами VAPID; сервис видит только факт и время сообщения. Тексты короткие («Claude закончил: …» либо текст запроса разрешения).

Если страница открыта и видна, уведомление не показывается. Ключи VAPID и подписки хранятся в `push.json` рядом с токеном (доступ только вам). Адреса подписок принимаются только от известных push-сервисов.

## Файлы и фото с телефона

Меню **⋯ → Прикрепить файл или фото**. Файл сохраняется в `<проект>/.claude-remote-uploads/` под случайным именем, а путь подставляется в ввод терминала, и `claude` читает файл по этому пути. Ограничения: 10 МБ; только PNG, JPEG, GIF, WebP, PDF и обычный текст (тип определяется по содержимому, а не по имени); внутри папки лежит `.gitignore` с `*`. В папке не больше 200 файлов; сама она не очищается.

Голосовой ввод отдельно не реализован: используйте микрофон на клавиатуре телефона, он работает в терминале как обычный ввод.

## Скриншоты нескольких мониторов

В окне «Экран» при нескольких мониторах появляется выбор экрана.

## Запись сессий (`--record`)

С флагом `--record` весь вывод каждого терминала пишется в `%APPDATA%\claude-remote\recordings\` (файл на сессию, ротация по 20 МБ, одна резервная копия). В записи остаётся **всё**, что показывалось на экране, включая пароли и ключи, поэтому по умолчанию она выключена, а файлы доступны только вашему пользователю. Вводимый вами текст отдельно не пишется (виден только его эхо).

## Модель угроз

**Что защищено**

- Порт слушает только Tailscale-адрес: он недоступен из интернета и из обычной локальной сети. Без Tailscale сервер не стартует.
- Любой запрос (страница, WebSocket, скриншот) требует токен: 32 байта из `crypto/rand`, сравнение в постоянное время (`subtle.ConstantTimeCompare`). Токен принимается только из cookie или заголовка `Authorization: Bearer`, **не** из строки запроса.
- Перебор токена: не более 5 неудачных попыток на IP за 5 минут, затем блокировка 1, 2, 4 … минут (до часа). Состояние в памяти.
- Защита от cross-site WebSocket hijacking и CSRF: обязательный `Origin`, равный `Host`; cookie `SameSite=Strict`. Защита от DNS-rebinding: `Host` должен быть IP-адресом или именем из `--allow-host`.
- Заголовки: CSP (`default-src 'self'`, без inline-скриптов), `nosniff`, `no-referrer`, `X-Frame-Options: DENY`.
- Клиент не может задать команду, папку или путь; файловых операций нет. Размер входящего WebSocket-кадра ограничен (256 КБ).
- В логах нет токена, cookie и содержимого терминала (проверяется тестом).
- Файл конфига доступен только вашему пользователю (ACL без наследования, проверяется при каждом чтении).
- При завершении сервера (и при его принудительном убийстве) всё дерево процессов убивается через Job Object.

- Загрузка файлов ограничена одной папкой проекта, случайными именами, белым списком типов по содержимому и лимитом 10 МБ; изменяющие запросы API требуют заголовок `X-CR` (без CORS-разрешений чужая страница его отправить не может).
- Push: адрес подписки принимается только у известных push-сервисов (иначе токен позволял бы заставить ноутбук обращаться к внутренним адресам), редиректы не выполняются.
- Приёмник событий от хуков слушает только `127.0.0.1` и требует секрет, который создаётся при каждом запуске и виден только процессам сессий.

- Закрытие сессий на ноутбуке требует подтверждения (и второго для работающей), проверяет процесс по имени и времени запуска и не принимает от клиента ни PID, ни пути.

- PIN-блокировка: см. раздел выше. Ключ разблокировки привязан к входу, живёт только в памяти страницы, не попадает в URL и логи, а сервер сам его отзывает при бездействии.
- Голосовой ввод уходит в Google через браузер (не через сервер), а текст проходит такой же путь, как обычный ввод.

- Сон, гибернация, перезагрузка и выключение требуют одноразового кода (30 секунд, привязан к входу и действию) и PIN, если он задан; для выключения и перезагрузки есть отмена. Эти действия отключаются флагом `--no-power`.

**Что НЕ защищено**

- Любой, у кого есть токен **и** доступ к вашей tailnet, получает полный шелл от вашего имени. Защитите аккаунт Tailscale (2FA) и токен (менеджер паролей).
- Любой процесс на ноутбуке под вашим пользователем может прочитать `config.json`, а любой, кто может сидеть за ноутбуком под вашей учётной записью, и так имеет всё.
- По HTTP без TLS cookie с токеном передаётся внутри туннеля WireGuard, но не защищена на уровне браузера. Другие устройства вашей tailnet могут пытаться подключаться (ограничьте их ACL в Tailscale).
- Любой процесс на ноутбуке под вашим пользователем (в том числе команды, которые запускает `claude`) видит секрет локального приёмника уведомлений и может слать вам ложные уведомления. Права на шелл он и так имеет.
- Скриншот показывает весь экран, включая уведомления и пароли, если они на экране.
- Вход живёт 14 дней в памяти сервера и не привязан к устройству. Отозвать: меню **⋯ → Выйти / Выйти везде** или перезапуск сервера (после `token rotate` он нужен в любом случае).
- **Cookie нельзя привязать к порту:** браузер отправляет её на любой порт того же адреса (`100.x.y.z:3000` и т. п.). Пока вы в сессии, не открывайте с телефона по адресу ноутбука чужие или недоверенные сервисы (например, dev-сервер, который запустил `claude`): он получил бы ваш вход. Для этого лучше сначала выйти (**Выйти**).

**Что делать при утечке токена**

1. `.\claude-remote.exe token rotate` (печатает новый токен).
2. Перезапустите сервер (`schtasks /End` и `/Run`).
3. Если подозреваете доступ к ноутбуку: удалите чужие устройства из Tailscale, смените пароль аккаунта, проверьте, что делал `claude` в истории терминала.

## Известные ограничения

- **Блокировка экрана**: на заблокированном экране скриншот чёрный или показывает экран входа (захват через GDI). Терминал при этом работает.
- Скриншот не показывает окна с защитой от захвата.
- Сессия **не переживает перезагрузку** ноутбука и завершение сервера: запускается новая.
- Буфер вывода 256 КБ: при подключении содержимое восстанавливается с ближайшей границы строки; цвета и режимы, заданные в отброшенной части, могут не восстановиться до следующей перерисовки программой.
- Дочерний процесс помещается в Job Object сразу после запуска; теоретически потомок, созданный в первые микросекунды, мог бы не попасть в него.
- Работа с реального телефона через Tailscale в разработке не проверялась автоматически: см. чек-лист в отчёте.

## Разработка

```powershell
gofmt -l .          # должен быть пустым
go vet ./...
go test ./...
govulncheck ./...   # go install golang.org/x/vuln/cmd/govulncheck@latest
```

Код, зависящий от ОС, разнесён на `*_windows.go` / `*_other.go`, поэтому `go vet` проходит и на Linux. Интеграционные тесты ConPTY запускаются только на Windows.

Версии и контрольные суммы xterm.js: `web/vendor/VERSIONS.md`.
